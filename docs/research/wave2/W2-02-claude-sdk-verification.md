# W2-02 - Claude SDK / Claude Code verification (wave two)

Researched 2026-10-07. Tags: [V] verified from a primary source I read in this session (URL given); [U] unverified. All Anthropic doc pages are undated and rendered live, so the fetch date is the citation date. The claude-code-action repo was cloned at commit 6fed3ca (2026-10-07).

## Summary

1. Most of doc 02's headless/SDK claims hold [V]. The material errors are: Sonnet 5.5 cache-read price ($0.10, not $0.20), the Max/Team credit coverage (the credits page says "Claude Code: No"; whether `claude -p` is covered is contradictory between two Anthropic pages), the auto-mode model list, "thinking cannot be disabled" on Sonnet 5.5 and Haiku 5.5, and the Prometheus exporter being offered for logs.
2. Auth: the actual terms text (quoted below) supports doc 02's recommendation (API key for a factory) but does not prohibit a personal always-on subscription setup. No Anthropic page I read addresses that case either way. Anthropic's own env-var docs describe `CLAUDE_CODE_OAUTH_TOKEN` as "Alternative to /login for SDK and automated environments", and the Legal page says Pro/Max limits "assume ordinary, individual usage of Claude Code and the Agent SDK". The BUILD_PLAN open question stays open but is now well bounded.
3. Three findings change the design: (a) `--max-budget-usd` does not count spend restored from earlier runs on `--resume`/`--continue`, so a per-attempt cap must be re-issued per invocation and the factory ledger must be the real budget; (b) Stop-hook continuation is capped (8 consecutive, reset by any tool call) and `/goal` is a wrapper over the same mechanism, so "keep going until CI is green" belongs in the orchestrator loop, with hooks as a backstop; (c) PreToolUse command hooks fail open on timeout and on non-2 non-zero exits, so safety must rest on deny rules and exit-2/JSON-deny, not on hook liveness.
4. Supervisor split: the SDK/Claude Code provide per-run caps, local session persistence and resume, an optional external SessionStore (Postgres/S3/Redis reference adapters), a local background-session daemon (`claude --bg`, `claude agents --json`, `claude respawn`), and in-session workflow replay. They provide nothing at goal level: no durable goal state machine, no cross-process lease, no cross-run ledger, no idempotent effect tracking, no escalation, and the daemon explicitly dies on reboot. The hand-rolled SQLite supervisor is still required, but can be made thinner (section 4).
5. Managed Agents is still beta, billed at list token rates plus $0.08 per running session-hour, covered by the Max/Team API credits ("Claude Managed Agents: Yes"; the session-hour line itself is not separately addressed [U]), not ZDR/BAA eligible, and its budgets are in cents and priced at list. Keep it as a deferred executor.
6. claude-code-action on self-hosted runners: no documented support, but the source contains explicit handling for "non-ephemeral self-hosted runners". Treat as plausible, untested.

## Verified findings

### A. `claude -p` flags and behavior

- `--bare`: "Minimal mode: skip auto-discovery of hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and CLAUDE.md". Claude keeps Bash, file read and file edit tools. It never reads OAuth or the keychain; auth is `ANTHROPIC_API_KEY` or `apiKeyHelper` in `--settings`; Bedrock/Vertex/Foundry credentials still work. `--bare` "is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release." In bare mode no background tasks run, system reminders are suppressed, and (v2.1.286+) only CLI-supplied MCP servers connect. [V] https://code.claude.com/docs/en/headless ; https://code.claude.com/docs/en/cli-reference
- Also: bare mode does not read `CLAUDE_CODE_OAUTH_TOKEN` and does not read Anthropic profiles or federation (WIF) variables. So WIF and `--bare` are mutually exclusive; with `--bare` use `ANTHROPIC_API_KEY` or `apiKeyHelper`. [V] https://code.claude.com/docs/en/authentication
- Without `--bare`, `-p` runs project hooks and `.mcp.json` servers "even in a folder you've never trusted", with no trust dialog. [V] headless.
- `--max-turns`: print mode only, "Exits with an error when the limit is reached. No limit by default." [V] cli-reference. SDK equivalent: result subtype `error_max_turns`; `maxTurns` counts tool-use turns only. [V] https://code.claude.com/docs/en/agent-sdk/agent-loop
- `--max-budget-usd`: print mode only, checked "against its client-side cost estimate, which can differ from your bill. Spend from subagents counts toward the cap. When you return to a conversation with `--continue` or `--resume`, totals restored from earlier runs don't count toward it." After the cap, spawning a subagent fails with `Budget limit reached` and background subagents are stopped (v2.1.217+). SDK subtype `error_max_budget_usd`. [V] cli-reference; agent-loop. Note the resume rule is a contradiction trap: `--output-format json` on a resumed run reports the whole conversation's cumulative `total_cost_usd` (headless page) while the cap ignores it.
- `--output-format`: `text|json|stream-json`. `stream-json` needs `--verbose`; `--include-partial-messages` adds deltas. The last line is a `result` message with cost and session metadata. `system/init` carries `mcp_servers`, `mcp_server_errors`, `plugins`, `plugin_errors`, and an optional `capabilities` array (v2.1.205+) for feature detection. `system/api_retry` carries `attempt`, `max_retries`, `retry_delay_ms`, `error_status`, and an `error` category enum (`authentication_failed`, `billing_error`, `rate_limit`, `overloaded`, `server_error`, ...). [V] headless.
- Result subtypes: `success`, `error_max_turns`, `error_max_budget_usd`, `error_during_execution`, `error_max_structured_output_retries`. All carry `total_cost_usd`, `usage`, `num_turns`, `session_id`. After a session crash the synthesized `error_during_execution` can have zeroed cost and `stop_reason: null`. `usage` covers only the main loop; use `modelUsage` for whole-tree accounting. `stop_reason: "refusal"` is how refusals surface. [V] agent-loop.
- Resume: `--continue`/`-c` (most recent in cwd; `-p --continue` includes `-p` sessions), `--resume <id|name|path.jsonl>` (cross-directory on one machine since v2.1.223), `--fork-session` (new ID when resuming), `--session-id <uuid>`, `--no-session-persistence` (print mode, nothing saved, cannot be resumed). [V] cli-reference; headless. `--system-prompt-snapshot`: by default a session records its system prompt on the first request and reuses it on resume, so changed `--append-system-prompt` text takes effect only after compaction or in a new conversation; in `--bare` recording is off unless `--system-prompt-snapshot on`. [V] cli-reference.
- Permission flags: `--allowedTools` (rule syntax; "Listing `Bash` ... except in a run that starts in auto mode, where Claude Code drops a bare `Bash` entry"), `--disallowedTools`, `--tools`, `--permission-mode {default|acceptEdits|plan|auto|dontAsk|bypassPermissions|manual}`, `--permission-prompts none` (v2.1.259+; denies and tells Claude not to retry), `--permission-prompt-tool`, `--restricted` (v2.1.248+: no command-running tools, refuses bypassPermissions, loads only managed settings and `--settings`). [V] cli-reference; headless.
- Signals: SIGTERM gives exit 143, leaves the turn unfinished with no result recorded, runs `SessionEnd` hooks only. SIGINT or SDK `interrupt()` ends the turn cleanly. `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` makes a resume continue the interrupted turn ("Used in SDK mode"). Background subagents/workflows keep `-p` open up to a 10-minute idle ceiling (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`, `0` = no ceiling). Piped stdin cap 10MB. [V] headless; https://code.claude.com/docs/en/env-vars
- Model fallback: `--fallback-model a,b` (comma list, max three after dedupe) triggers on overloaded/unavailable/non-retryable server errors; "never" on authentication, billing, rate-limit, request-size, transport errors. Separate automatic safety-classifier fallback: Fable 5.1, Fable 5, Opus 5.5 re-run on Opus 4.8 (cyber flag) or Opus 5 (biology flag); Sonnet 5.5 re-runs on Sonnet 5 (cyber) and simply refuses (no fallback) on biology. Requires v2.1.219+. A fallback is a model switch, so it forfeits the cache. [V] https://code.claude.com/docs/en/model-config ; https://code.claude.com/docs/en/prompt-caching

### B. Agent SDK sessions, resume, fork

- A session is the conversation only; "Sessions persist the conversation, not the filesystem." Files: `~/.claude/projects/<encoded-cwd>/*.jsonl` (under `$CLAUDE_CONFIG_DIR/projects/` if set). Options: `continue`, `resume`, `forkSession`/`fork_session` (copies history into a new session ID, original unchanged, filesystem not branched), `persistSession:false` (TypeScript only). `ResultMessage.session_id` is present on every result "regardless of success or error"; a single-shot `query()` raises after yielding an error result, so wrap it. Recovery from `error_max_turns`/`error_max_budget_usd` is explicitly "resume with a higher limit". [V] https://code.claude.com/docs/en/agent-sdk/sessions
- Cross-host: files are local. Options: a `SessionStore` adapter (`append` and `load` required; `listSessions`, `listSessionSummaries`, `delete`, `listSubkeys` optional), move the `.jsonl`, or "Don't rely on session resume. Capture the results you need ... as application state and pass them into a fresh session's prompt. This is often more robust than shipping transcript files around." Reference adapters (S3, Redis, Postgres) live in the SDK repos' `examples/` and "are not published as packages". The store is a best-effort mirror: local write first, up to 3 attempts, then `mirror_error` and the batch is dropped; dedupe by `entry.uuid`; a run resumed from the store deletes its local copy, so a dropped batch has no surviving copy. `persistSession:false` and file checkpointing conflict with a store. [V] https://code.claude.com/docs/en/agent-sdk/session-storage
- Compaction: auto-compaction emits `system/compact_boundary`; `PreCompact` hook receives `trigger` (`manual|auto`); `getSessionMessages` after compaction returns the post-compaction chain, not the raw history. [V] agent-loop; session-storage.

### C. Hooks

- 33 events and 5 handler types (`command`, `http`, `mcp_tool`, `prompt`, `agent`). [V] https://code.claude.com/docs/en/hooks (read characters 0-200000 of 250538).
- Stop: `decision:"block"` + `reason` (or exit 2 with stderr) prevents stopping. Input includes `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`. "Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn. The count of consecutive continuations resets each time Claude calls a tool." Override with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`. `additionalContext` is the non-error variant under the same protections. SubagentStop uses the same block format. [V] hooks.
- PreToolUse: exit 2 blocks (stderr to Claude); "Other non-zero exit codes: Non-blocking. The action proceeds". JSON `hookSpecificOutput.permissionDecision` is `allow|deny|ask|defer`; `updatedInput` rewrites arguments; precedence `deny > defer > ask > allow`; deny/ask rules "are still evaluated regardless of what the hook returns". "A timed-out `command`, `http`, or `mcp_tool` hook doesn't block the call"; an SDK callback hook that times out does block. [V] hooks.
- Deny rules apply in every mode including `bypassPermissions`; allow rules have no effect in `bypassPermissions`. [V] https://code.claude.com/docs/en/permission-modes
- `/goal` "is a wrapper around a session-scoped prompt-based Stop hook"; the evaluator (small fast model) sees only what is in the conversation, condition up to 4,000 chars; works with `-p` ("runs the loop to completion in a single invocation"); clears on auth failure, exhausted credit, unrecoverable context overflow or unavailable model; unavailable if `disableAllHooks` or `allowManagedHooksOnly`; gated by workspace trust. In `-p` it does not auto-wait on usage limits. [V] https://code.claude.com/docs/en/goal

### D. Permission modes

- Modes: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. `dontAsk` denies anything not pre-approved ("useful for locked-down CI runs"). `bypassPermissions` "Isolated containers and VMs only"; Claude Code refuses it as root/sudo on Linux/macOS unless in a recognized sandbox ("--dangerously-skip-permissions cannot be used with root/sudo privileges"). A `-p` run with `--dangerously-skip-permissions`: "the few calls that would still prompt are denied instead". Project `settings.json` cannot set `auto` or `bypassPermissions` as `defaultMode` (silently ignored). [V] permission-modes; headless.
- Auto mode model support on the Anthropic API: "Claude Opus 4.6 or later, Sonnet 4.6 or later, Haiku 5.5, or a Fable model"; the stricter list (Sonnet 5+, Opus 4.7+) applies only to Bedrock/Vertex/Foundry. Classifier calls count toward token usage on API-key accounts. In `-p`/SDK sessions on a direct API connection the classifier path requires v2.1.281+. [V] permission-modes.

### E. Subagents and workflows

- `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` default 3 (1 disables nesting), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` default 20; both v2.1.217+. [V] env-vars.
- Dynamic workflows: JS script orchestrating subagents; up to 16 concurrent agents by default (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` 1-256), 1,000 agents per run, 4,096 items per `parallel()`/`pipeline()`; no module loading or direct fs/shell in the script; `Date.now()`/`Math.random()` throw so replay is deterministic. Resumable "within the same Claude Code session" (replay returns saved results for completed agents; first diverging or failed agent and everything after it reruns). In `-p`/SDK there is no approval prompt; a `Workflow` allow rule, auto mode, bypass, hook, or `canUseTool` must approve. The `ultracode` keyword does not trigger from `-p`. Usage-limit auto-pause does not apply in `-p`. [V] https://code.claude.com/docs/en/workflows
- Subagent cache: subagent/workflow requests use a 5-minute TTL bucket by default even on a subscription; set `subagentPromptCacheTtl`/`CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` to `1h`. [V] https://code.claude.com/docs/en/prompt-caching

### F. Background-session supervisor ("agent view")

- `claude --bg`, `claude agents [--json]`, `claude attach|logs|stop|respawn|rm`, `claude daemon status|logs|run|stop`. The supervisor keeps sessions alive after the terminal closes; roster at `~/.claude/daemon/roster.json`; per-session state under `~/.claude/jobs/<id>/state.json` ("Reading this file directly isn't a stable interface"). Exited processes are restarted by the supervisor. Idle unattended sessions are stopped after about an hour unless pinned. "Shutting down or restarting your machine stops running background sessions": within 48h they show as failed and restart on attach/reply; after 48h they show stopped and need confirmation. A session on a permission prompt shows `Needs input` and makes no progress. "Local only". Auth is "the same stored credentials as your interactive sessions" and an expiring OAuth login stops unattended progress. `--bg` cannot be combined with `-p`. [V] https://code.claude.com/docs/en/agent-view ; cli-reference (read characters 0-100000 of 133683).

### H. Rate limits (org-level, per model class)

- Spend caps: Start $500/month, Build $1,000, Scale $200,000; reaching one gives HTTP 429 `enforced_spend_limit_reached` with no `retry-after` until 00:00 UTC on the 1st. A self-set limit gives HTTP 400. [V] https://platform.claude.com/docs/en/api/rate-limits
- Start tier, Opus 5.5 / Sonnet 5.5 / Haiku 5.5 each: 1,000 RPM, 2,000,000 ITPM, 400,000 OTPM; Fable 5.x: 1,000 RPM, 500,000 ITPM, 100,000 OTPM. Build: 5,000 RPM, 5M ITPM, 1M OTPM (Fable 2,000 / 1.5M / 300K). Scale: 10,000 / 10M / 2M (Fable 4,000 / 4M / 800K). Cache-read tokens do not count toward ITPM (except Haiku 3.5); cache-creation tokens do. Managed Agents: 300 create and 1,200 read requests per minute per org. New orgs may start in an Evaluation tier with lower limits. Linked Max/Team credits lift an org to at least Start (Build if credits exceed $200). [V] same page; credits page.
- Claude Code traffic uses a "Claude Code workspace" whose limits are checked separately and can return 429 with `retry-after`. [V] rate-limits page (link to workspaces doc not followed).

### I. Prompt caching in Claude Code

- Cache is prefix-exact and per model; switching models, MCP tool-set changes (without tool search), compaction, upgrading Claude Code, and (on older models) effort changes invalidate it. On Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 an effort change keeps the cache. [V] https://code.claude.com/docs/en/prompt-caching
- TTL defaults: main conversation (interactive, `-p`, SDK) gets 1 hour only on a Claude subscription within plan usage; with an API key, usage credits or a cloud provider the main conversation gets 5 minutes; everything else (subagents, workflows, compaction, teammates) gets 5 minutes. Set `CLAUDE_CODE_PROMPT_CACHE_TTL=1h` or `promptCacheTtl` (v2.1.242+) for the main bucket, `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` for the rest, `ENABLE_PROMPT_CACHING_1H=1` for both, `FORCE_PROMPT_CACHING_5M=1` to force 5m. Confirm with `claude -p "hello" --output-format json` and read `usage.cache_creation.ephemeral_1h_input_tokens`. Cache is "effectively scoped to one machine and directory" (the system prompt embeds paths); `--exclude-dynamic-system-prompt-sections` improves cross-machine reuse. [V] prompt-caching; cli-reference.
- Caching math: 5m write 1.25x, 1h write 2x, read 0.1x (0.05x on Opus/Sonnet 5.5). [V] pricing.

### J. OpenTelemetry

- Off by default; `CLAUDE_CODE_ENABLE_TELEMETRY=1`; metrics exporters `otlp|prometheus|console|none`; logs exporters `otlp|console|none` (no Prometheus for logs); must set `OTEL_EXPORTER_OTLP_PROTOCOL`. Metrics: `claude_code.session.count`, `lines_of_code.count`, `pull_request.count`, `commit.count`, `cost.usage`, `token.usage`, `code_edit_tool.decision`, `active_time.total`. Events include `user_prompt`, `tool_result`, `tool_decision`, `api_request`, `api_error`, `api_refusal`, `api_retries_exhausted`, `permission_mode_changed`, `auth`, `mcp_server_connection`, `skill_activated`, `hook_registered`. Traces are beta (`CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` + `OTEL_TRACES_EXPORTER`); `-p` and SDK sessions read inbound `TRACEPARENT`/`TRACESTATE`; event records carry `trace_id`/`span_id` even without a traces exporter; `app.entrypoint` distinguishes `sdk-cli|sdk-ts|sdk-py`. Content is redacted by default (`OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS`, ...); repo settings cannot enable telemetry or set its endpoint; `OTEL_*` variables are not passed to subprocesses. [V] https://code.claude.com/docs/en/monitoring-usage (read 0-100000 of 149353). The page does not say how bare mode interacts with telemetry [U].

### L. claude-code-action

- Interactive vs automation mode (prompt set => runs on any event including `schedule`); `claude_args` passes any CLI flag; auth by `anthropic_api_key`, `claude_code_oauth_token`, Bedrock/Vertex/Foundry via OIDC, or workload identity federation (`anthropic_federation_rule_id`, `id-token: write`). Default `GITHUB_TOKEN` pushes do not trigger CI; bots rejected unless in `allowed_bots`; write access required on issue/PR events. The Costs section says: "the Claude Code GitHub Action runs on GitHub-hosted runners, which consume your GitHub Actions minutes." [V] https://code.claude.com/docs/en/github-actions
- Self-hosted: no documented support or requirements. Source evidence in the cloned repo: `src/create-prompt/index.ts` and `src/modes/agent/index.ts` clear stale prompt files because "on non-ephemeral self-hosted runners this [RUNNER_TEMP cleanup] is not reliably honored"; `action.yml` installs the bubblewrap isolation "Best-effort: skips on non-Linux or when sudo/apt unavailable (self-hosted runners)"; FAQ documents `path_to_claude_code_executable` and `path_to_bun_executable` and says "The action will skip automatic installation when custom paths are provided"; the README says it "executes entirely on your own GitHub runner". [V] repo clone at https://github.com/anthropics/claude-code-action (commit 6fed3ca); https://raw.githubusercontent.com/anthropics/claude-code-action/main/docs/faq.md . Conclusion: self-hosted runners are anticipated by the code but unsupported in docs; test before relying.
- Docs name a different product: "self-hosted environments" (`claude self-hosted-runner`, `claude --cloud`/`--environment ccpool_...`) running Claude Code cloud sessions on your infrastructure. It is public beta on Team and Enterprise only, off by default, session content still goes to Anthropic, not ZDR/HIPAA. Not usable for a personal Max/API-only setup. [V] https://code.claude.com/docs/en/self-hosted-environments

### M. Managed Agents

- Beta (`managed-agents-2026-04-01`; "Behaviors may be refined between releases"). Enabled by default for all API accounts. MCP tunnels and dreaming are "a more limited research preview". "Not currently eligible for Zero Data Retention or HIPAA BAA". [V] https://platform.claude.com/docs/en/managed-agents/overview

### N. Anthropic engineering posts: extracted design rules

All four read directly. URLs in Sources.

Effective harnesses for long-running agents (2025-11-26): (1) first session sets up environment (feature list, `init.sh`, progress log, initial commit); later sessions make incremental progress on one feature; (2) bridge context windows with persistent artifacts: JSON feature list (agents may only flip `passes`; "It is unacceptable to remove or edit tests"), progress file, git history, `init.sh`; (3) JSON beats Markdown for state the model must not clobber; (4) end each session clean (commit, progress note, no half-done work); (5) test end to end as a user (browser automation), models otherwise mark features done prematurely; (6) fixed session-start routine: `pwd`, read git log and progress, pick top unfinished feature, run `init.sh` plus a smoke test.

How we built our multi-agent research system (2025-06-13): orchestrator-worker; explicit effort-scaling rules in prompts (1 agent / 3-10 tool calls for simple lookups, >10 subagents for complex); token usage alone "explains 80% of the variance"; agents use about 4x chat tokens and multi-agent about 15x; Opus lead + Sonnet subagents beat single Opus by 90.2% on their internal eval; each subagent needs objective, output format, tool guidance, task boundaries; start evals with about 20 queries; single-call LLM judge scoring 0.0-1.0 was most consistent; judge outcomes not paths; "resume from where the agent was when the errors occurred", combine adaptive behavior with "deterministic safeguards like retry logic and regular checkpoints"; rainbow deployments so running agents are not disrupted; multi-agent poorly suited to tasks sharing one context or with many dependencies, "most coding tasks".

Demystifying evals for AI agents (2026-01-09): prefer code graders, then model graders, humans for calibration; check outcome in the environment, not the agent's claim; pass@k vs pass^k; capability evals start at low pass rate, regression evals near 100%; each trial starts from a clean environment; read transcripts; 20-50 tasks from real failures is a good start; two experts should reach the same verdict; give model judges an "Unknown" exit and grade each dimension with a separate judge; near-0% pass across trials usually means a broken task or grader.

Harness design for long-running application development (2026-03-24): separate generator from evaluator ("a strong lever"); out of the box Claude is "a poor QA agent" and must be tuned against your own judgment by reading its logs; sprint contracts (agree what "done" means before coding); context resets vs compaction depends on model (resets needed for Sonnet 4.5's "context anxiety", dropped for Opus 4.5); keep the planner high-level; stress-test each component, since each encodes an assumption that goes stale; cost reference points: solo $9 / 20 min vs full harness $200 / 6 h on Opus 4.5.
